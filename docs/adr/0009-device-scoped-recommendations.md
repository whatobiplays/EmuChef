# ADR 0009: Device- and brand-scoped recommended setups

**Status:** Accepted product direction; recommendation evidence and implementation details open.

EmuChef's primary experience offers a small number of meaningful choices, recommendations, and sensible defaults with advanced settings progressively disclosed. Device Profiles identify hardware and capabilities. Device Plans own recommended Recipe composition and app-setting values for supported device models and brand families; App Definitions own setting semantics and validity. Applicability ranks exact model before brand family before a device-independent baseline. Equal-specificity recommendation-match ambiguity is an error, not resolved by catalog loading order. Model-specific settings cannot silently become global recommendations.

Compatibility requirements are enforced, while recommended values can be changed to other valid values. An unknown exact device may use only explicitly supported generic capabilities, not inferred model-specific settings. The consumer UI identifies the source of meaningful defaults and allows restoration of recommended values. An explicit valid user choice outranks device recommendations. At lower priority, exact-model recommendations outrank brand-family recommendations, which outrank generic baselines. Equal-priority property writes from different Recipes use the last writer in a deterministic, reviewed order; this rule does not override safety and compatibility requirements, or suppress equal-specificity device-match ambiguity errors. Saved valid explicit choices remain in effect across devices, with warnings when a retained override is inappropriate for the new device; invalid choices require correction. The existing `overrides.config_variants` entries are metadata only and cannot supply real planner bindings without implementing that capability.

## Open engineering contract (not implemented)

[EmuChef product realignment proposal](../product/emuchef-product-realignment-proposal.md) assigns T07 property semantics, T11 deterministic recommendation matching and sanitized provenance, and T05b cross-device user override re-evaluation. T09 resolves competing Recipe property intents for the same destination before review: explicit valid user values prevail; model over brand over generic; same-priority last writer follows a stable reviewed execution order. These are requirements, not operational claims about current metadata-only `config_variants`.
