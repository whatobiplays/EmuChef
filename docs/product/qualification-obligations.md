## Disposition rules

1. **Applicable:** an obligation closes only with the qualifying records specified by its original evidence/acceptance contract. If missing/deferred, it blocks the corresponding capability or release gate.
2. **Inapplicable:** only when a release scope has been **expressly approved** and excludes that target/feature, with a reasoned contract-grounded determination recorded by T17Q; not an ad hoc waiver.
3. **Superseded:** requires explicit explanation, equivalent or stronger replacement evidence, and required owner/security/qualification approval. Historical roadmap retirement by itself is never supersession.
4. **Qualification runs:** owner sequencing approval is not physical operator/target consent. Individual devices, temporary paths, root/permission actions, builds and run scopes need separate authorization and preflights. Do not promote old dry-run, AVD or registered-profile data to new physical target coverage.
5. **Authority after T02:** [GitHub map](https://github.com/whatobiplays/EmuChef/issues/43)/child tickets track **work status**, this inventory tracks obligation routing, source evidence and validators track **actual pass/fail**. Keep these distinct. No manual or physical work was executed for this documentation update.
