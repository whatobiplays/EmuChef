## Disposition rules

1. **Applicable:** Close only with evidence meeting the original contract and exact target/build requirements. Missing applicable evidence blocks the affected capability or release claim.
2. **Inapplicable:** Use only an already approved release boundary and record a contract-grounded reason. T17Q creates no exclusions, waivers, or approvals.
3. **Superseded:** Require an explicit reason, equivalent or stronger replacement evidence, and applicable owner, security, or qualification approval. A roadmap status change alone is not supersession.
4. **Physical execution:** Owner sequencing is not run authorization. Device, build, action, path, and run scope require separate authorization and preflight.
5. **Status separation:** Issue status tracks work; this register tracks routing; source records and validators determine evidence status. T03/T07 implementation closure does not imply product or device qualification.

This register and its linked inventory complete T17Q routing for owner review. Missing physical, manual, workflow, signing, and trust evidence remains visible and blocks the affected capability or release. Inventory closure is not qualification closure.
